# Contributing to Refella

Thanks for helping build Refella.

## Propose a change

Open an issue describing the customer or business problem, the proposed change, and how success can be checked. For implementation work, identify the relevant item in the [roadmap](docs/ROADMAP.md).

## Submit a pull request

Keep each pull request focused. Explain the problem, what changed, how it was verified, and any limitations. Update the README when the setup process or actual implementation status changes.

Do not commit credentials, real customer conversations, phone numbers, or payment data. Use synthetic examples and document required configuration with placeholder values.

## Keep the presentation accurate

Label proposed features and simulated integrations clearly. Only add screenshots, demo links, test results, and supported-channel claims that have been verified against the implementation.

No license has been selected yet. Do not assume that public visibility grants permission to reuse the code under an open-source license.
