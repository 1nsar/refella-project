# Operating contract

- Repository is confidential. Do not change visibility or copy its full contents/history into a public submission. Public exports require a deliberate file allowlist and secret/data review.
- Read `docs/PRODUCT.md` before strategy, implementation scope, public copy or video work. It is the canonical product truth. Dated research and earlier chat phrasing do not override it.
- For content/video work, also read `docs/DEMO-BRIEF.md` and `docs/EVIDENCE.md`. A proposed flow is not implemented behavior. Record exact observed capabilities before presenting them as working.
- Preserve the user's one-liner and no-install mechanism. Do not turn this into a consumer app, full CRM/POS replacement, marketplace or restaurant inventory product without explicit approval.
- Keep proposed, approved, implemented and verified separate. Update evidence and decisions when status changes.
- Production repository does not mean production-ready. No live deployment, real payout, mass message or production data import without authorization.
- Tenant derives from authenticated integration/channel context, not model text. Authorize every operation. No cross-tenant customer data sharing by default.
- Models do not establish payment truth or calculate rewards outside versioned rules. Signed source events or authorized staff establish conversions; backend rules and transactions control rewards.
- No credentials, real phone numbers, payment details or customer conversations in git/demo. Use synthetic fixtures. Keep secret keys server-side.
- Do not edit the colleague's landing page without checking ownership and existing changes. No new agents/tasks need to be launched merely because these docs mention a downstream content agent.
- Preserve short concrete Russian/English language. Do not invent proof, adoption, partnerships, uniqueness, financial returns or polished UI that does not exist.
