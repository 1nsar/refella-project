# Подключение бизнеса и путь клиента

Статус: предлагаемая схема, не реализованная интеграция. 12 сентября 2026.

## Три способа подключиться

| Ситуация бизнеса | Подключение | Кто разговаривает с клиентом |
|---|---|---|
| Есть агент с возможностью вызывать API/tools | Владелец выдаёт ограниченный доступ к реферальному сервису; разработчик добавляет действия создания приглашения и проверки статуса | Существующий агент; наша система возвращает данные |
| Есть канал, агента нет | Подключаем разрешённую интеграцию канала и отдельный сценарий обслуживания | Наш агент, с передачей администратору |
| Существующий сервис закрыт для интеграции | Отдельная ссылка/реферальный чат, подтверждение результата через администратора | Отдельный сценарий; переход между чатами показываем честно |

API или MCP не подключаются к произвольному чужому боту автоматически: его платформа должна разрешать расширение. Два агента не должны независимо отвечать на одно сообщение.

## Путь владельца

1. Создаёт организацию и указывает ответственного сотрудника.
2. Выбирает способ подключения; подтверждает доступ к каналу или выдаёт интеграционный ключ с ограниченными правами.
3. Настраивает одну программу: кто считается новым клиентом, условие визита/покупки, обе награды, сроки, лимиты, отмены.
4. Выбирает источник подтверждения: интеграция записи/кассы или сотрудник. Ручной режим маркируется в интерфейсе.
5. Проходит тестовое приглашение и отмену. Включает программу после проверки.
6. Видит приглашения, подтверждённые результаты, ожидающие проверки и журнал наград. Может приостановить программу без потери истории.

## Путь приглашающего

Клиент просит приглашение в чате бизнеса. Система проверяет условия, выдаёт ссылку/код и объясняет награду. Клиент сам отправляет приглашение другу. Он может спросить свой баланс и статус награды; подробности чужой покупки ему не раскрываются.

## Путь друга

Друг открывает приглашение и сам начинает разговор с бизнесом. Система проверяет код и связывает его с программой. Если код не передан или изменён, запрашивает его, а не угадывает рекомендателя. Агент объясняет условия, отвечает на вопросы и предлагает доступную запись. Бронь считается созданной только после успешного ответа системы записи.

После визита приходит событие из доверенного источника или авторизованный сотрудник отмечает факт. Backend проверяет правила и создаёт награды. Внутренний бонус отображается в журнале; его погашение требует отдельной подтверждённой операции. Сообщение «я оплатил» не подтверждает платёж.

## Минимальная техническая схема

```text
Канал / существующий агент
  → проверка источника и определение бизнеса
  → диалог и разрешённые действия
  → referral API → правила и журнал
                      ↑
             подтверждённый визит / заказ
```

Бизнес определяется по проверенному подключению канала или учётным данным интеграции. `tenant_id` не берётся на доверии из текста пользователя или ответа модели. Каждая операция проверяет права на клиента, программу и событие внутри этого бизнеса.

Храним отдельно:

- Referral: программа, рекомендатель, приглашённый, код, время и основание атрибуции.
- Booking/conversion: внешний ID записи или заказа, источник, статус, подтверждающий сотрудник при ручном режиме.
- Reward ledger: получатель, сумма/единица, основание, начисление, погашение и корректирующие записи.

Повторная доставка одного события не должна начислять награду второй раз. Ключ уникальности включает бизнес, внешнюю конверсию, программу, получателя и вид награды. Политика смены правил версионируется; повтор старого события не пересчитывается по новой акции.

AI формулирует ответ и выбирает разрешённое действие. Правила программы определяют eligibility и сумму. Только авторизованный источник подтверждает визит. Сбой отправки уведомления не отменяет начисление и не разрешает начислить его снова.

## Прототип хакатона

Один бизнес, один канал, одна программа, две клиентские роли, сотрудник для подтверждения визита. Если система записи тестовая, это обозначается в демо. Второй тестовый бизнес нужен для проверки изоляции, а не для расширения функций.

Демонстрация: приглашение → разговор друга → подтверждённая запись → отметка визита → награда → повтор события без повторного начисления. Не симулировать рабочую кассу или реальные выплаты, если их нет.

Для production отдельно проверить условия сообщений выбранного канала, согласия, учёт персональных данных и доступность интеграции. Их нельзя вывести из того, что тестовый бот работает.
